- Product version `v1.0.0`; build code `66`, retaining monotonic Android ordering after build `65`.
- App identity remains `cn.com.letalk.navo`; Android APKs require the existing fork signing key for an in-place update. All four required Android signing secret names were present; values were not logged.
- Windows installer ProductVersion changes from `2.12.65` to `1.0.66` under the same fork upgrade UUID. Same-identity local 2.12.x development installers need a settings backup and manual uninstall/replacement; the in-app SemVer checker will not offer a downgrade to 1.0.0.

## Paused-seek publication correction

- Shared native polling can enter `NaviampCorePlaybackEngineAdapter.onProgressChanged` before a paused seek invalidates the request, then finish its settings/native work afterward. The former entry-only check allowed that old callback to overwrite the pending seek and saved resume position.
- A short common `atomicfu` publication barrier now couples paused-seek invalidation with the callback's final eligibility check and observer publication. Cancellation and native cleanup stay outside the barrier; there is no added per-tick coroutine or change to polling frequency. The pinned atomicfu 0.28.0 dependency was already present in the bundled runtime.
- Added a common reentrant regression and a JVM latch-controlled concurrent callback regression. The original real mTLS contract and its range, trust, timeout and recovery assertions remain unchanged.
- `adb devices -l` reported no connected local emulator/device. Native verification therefore remains the complete API 35 candidate gate. Apple compilation is unavailable on this Windows host and Apple product pipelines remain disabled.
- Local verification passed in 5m12s: `:core:presentation:jvmTest` filtered to the complete `NaviampCorePlaybackEngineAdapterTest` and new `NaviampPausedSeekConcurrencyTest`, plus `:core:presentation:compileAndroidMain` in one serialized invocation. Existing native mTLS assertions were not changed.
