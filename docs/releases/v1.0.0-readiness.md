## Version and installation decisions

- Product version `v1.0.0`; build code `66`, retaining monotonic Android ordering after build `65`.
- App identity remains `cn.com.letalk.navo`; Android APKs require the existing fork signing key for an in-place update. All four required Android signing secret names were present; values were not logged.
- Windows installer ProductVersion changes from `2.12.65` to `1.0.66` under the same fork upgrade UUID. Same-identity local 2.12.x development installers need a settings backup and manual uninstall/replacement; the in-app SemVer checker will not offer a downgrade to 1.0.0.
- Upstream app identities and earlier local `cn.com.letalk.naviamp` identities remain separate. No automatic data or credential migration is promised.
- Expected public assets: one signed Android APK and Windows ZIP/MSI/EXE. AAB, R8 mapping and native symbols remain in `android-publishing-support` Actions artifacts, not public release assets. No store publication is implied.
- Windows packages are not publisher-signed. Release packaging requires the pinned patched Corretto 21 runtime; the local development JDK is not release-runtime evidence.

## Verification and publication gates

Preparation is not publication. The release remains gated until all of the following evidence is recorded:

1. Local version/tag validators and release-announcement helper contracts pass.
2. Shared About/changelog/update-checker suites pass, with actual About rendering, full scrolling and TV focus coverage; inspect captured screenshots.
3. Implementation checkpoint review passes and selective release-preparation commit is pushed to `main`.
4. A blank-tag `Tag release builds` dispatch passes the full Windows/Android matrix and both packaging jobs before tagging the accepted source.
5. The immutable `v1.0.0` tag workflow passes its complete verification/packaging gates and creates a draft.
6. Review draft title exactly `Navo v1.0.0`, notes, four expected assets, Android signature/package/version and Windows package/runtime metadata before publishing.
7. Read back the published release title, tag and assets. Keep the release tag immutable; later evidence-only documentation commits do not alter released source.

Real vehicle hardware, Apple/Linux hosts, and store review are outside this release's acceptance. JVM rendered tests are shared About proof, not physical-device or installer proof.
